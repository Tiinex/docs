# From a Goal to Work You Can Keep

People start with ideas, not with record types. *“I want to build a small board game.”* The first useful response may be a design sketch or a question about what kind of game you like.

## Help first, organize when useful

Explore the idea together. When work becomes something you want to develop over time, the assistant should determine whether it belongs with an existing project or needs its own place. One ordinary question is often enough: *“Would you like me to keep this as part of your project so we can work on it later?”*

A small project may benefit from a clear goal and a next step. A repeated activity may benefit from a reusable way of working. A group may need explicit responsibilities. **None of these should be created merely because Tiinex supports them.**

## What the assistant does behind the scenes

When qualified Tiinex support is available, the assistant discovers the currently supported record types, examines their actual schemas and companions, and chooses a proportionate way to preserve the work. It must check real Parent and source relationships rather than invent an appealing folder structure. Custom imported schemas can be considered on the same terms as built-in ones.

If the host cannot qualify or save a record, the assistant should explain the limitation. It must not present an unqualified Markdown file as a verified Tiinex record.

## A small example

You start with a game idea, then create a printable first version. When you ask to keep working on it later, the assistant can save the useful game files **and** the relevant project context if the Workspace relationship and capabilities are established. Merely producing a ZIP or keeping a chat open does not necessarily preserve qualified continuity.
