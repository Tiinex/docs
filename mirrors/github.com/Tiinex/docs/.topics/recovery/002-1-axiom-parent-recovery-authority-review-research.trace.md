# Parent Recovery Authority Review — Axiom Research Result

## Research Question

- Question: does the landed Root recovery candidate state the smallest safe canonical contract for truthful Parent recovery, exact published schema references, and bounded transport recovery before Loom implements scoped export behavior?

## Source Field

- In Scope: the carried Tiinex/docs Root candidate, the preceding Parent Origin recovery discovery, the incoming Anchor-to-Axiom Handoff, canonical Handoff and Semantic Package transport boundaries, and the complete carried Docs source needed to test consistency.
- Out Of Scope: filename/carrier dimension policy, Viewer UX, shared Tooling implementation details, remote publication, and fresh repository material outside the carried source chain.
- Source Or Origin: exact inherited Docs workspace bytes from the qualified Handoff carrier; no remote checkout substituted for continuity.

## Method

- Method: compare Root machine-authoritative Parent Origin and Schema Reference Fields rules against the recovery discovery's local, external, schema-publication, transport, and fail-closed boundaries; test same-materialization, cross-repository published, unpublished external, and bounded-export cases; inspect neighboring canonical package/Handoff semantics for conflicting authority.
- Boundary: accept the landed wording only where it independently preserves semantic Parent identity, source/representation truth, exact schema authority, and failure closure. Apply only the smallest canonical correction required; leave runtime/export mechanics to Loom.

## Findings

- Parent Origin: confirmed. Root correctly requires at least one truthful Parent recovery locator, requires `relative` when the exact Parent is directly recoverable in the same qualified materialization/source scope, forbids manufacturing duplicate Parent copies merely to satisfy locality, and requires a qualified version-stable route when no truthful local relative route exists.
- External recovery: confirmed. `browse + git` is correctly treated as one adapter form only when an immutable Git revision identifies the exact published Parent representation; mutable branch/latest locators do not qualify as version-stable recovery.
- Schema references: confirmed. Root correctly separates schema semantic identity from representation location. For a published artifact referencing a different already-published canonical schema representation, an immutable canonical locator is required when available; relative/local locators remain valid for local or unpublished work, a self-relative schema link remains valid for self-reference, and publication tooling must not fabricate future immutable locators.
- Transport boundary: correction required. The landed single sentence that package/transport closure may provide additional recovery was directionally correct but insufficiently explicit about authority and failure. Without a sharper separation, an exporter could over-read transport metadata as curing a source artifact with missing/false `Origin`, or preserve a broken recovery edge without a fail-closed condition.
- Canonical correction: Root now states that package/transport closure is separate from the Parent artifact's own `Origin` contract; closure may preserve or augment an already-truthful Parent edge but cannot make an invalid/missing source Origin valid. If bounded transport would make all declared or otherwise qualified Parent recovery routes unusable, Tooling must preserve an exact recovery mapping/representation, rely on an already-qualified version-stable route, expand scope, or fail closed.
- Corrected Root self seal: `opA3uerTJ6TK8hyt1wbI-cZZZDgE_Z0aaFCmbAbwB4A` under `sha256-base64url-c14n-v2`.
- Tooling qualification discrepancy: the current portable audit reports `integrity.method-reference.unqualified` for Root because its self-integrity entry uses the plain canonical method identifier. Root's machine contract explicitly allows `Plain Method Identifier`, so Axiom does not tighten canonical Root semantics merely to satisfy this runtime policy. Loom must reconcile that validator behavior before treating the audit error as authoritative for scoped export.
- Loom consequence — Parent validation: preserve relative-only local continuation when the Parent is directly recoverable; accept qualified version-stable external continuation without fabricated relative locality; reject zero truthful recovery routes.
- Loom consequence — export boundary: detect when bounded export makes the recipient unable to use all Parent recovery routes. Satisfy the boundary only through exact carried recovery mapping/representation, an already-qualified version-stable external route, scope expansion, or explicit failure.
- Loom consequence — authority separation: package closure, archive placement, and carried copies must not rewrite `Trace`, semantic Parent identity, source publication provenance, or canonical schema identity. A package copy is recovery material unless separate authority says otherwise.
- Loom consequence — schema publication: when publishing a new or materially updated artifact that references a different already-published schema and an immutable canonical representation locator is available, emit that exact immutable locator; do not treat mutable branch/latest or a convenient relative copy as equivalent exact authority, and do not invent a permalink for local/unpublished schema material.

## Synthesis

- Synthesis: no schema-semantic blocker remains for Loom after the narrow Root transport-boundary correction. The landed Parent Origin and schema-reference rules are otherwise confirmed. The governing distinction is now explicit: artifact `Origin` owns truthful Parent recovery authority, while transport closure may preserve or augment recipient recovery but cannot retroactively create source Origin truth or semantic Parent identity. One Loom-owned runtime validator mismatch remains: portable audit currently over-constrains Root's allowed plain integrity method label.
- Governing Docs: `.topics/.schemas/tiinex.root.v1.schema.md` with self seal `opA3uerTJ6TK8hyt1wbI-cZZZDgE_Z0aaFCmbAbwB4A`, together with this review result for implementation-facing interpretation.
- Remaining Work: Loom may implement the scoped-export checks above; Anchor retains filename/carrier dimension policy and should reconcile this return into the wider Foundation sequence.

## Interpretation Limits
