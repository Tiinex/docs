# Chat-First Documentation and Topic Scope Revision

## Objective

Revise the pending Docs Documentation lineage for a first-time person who starts by talking in chat rather than operating a terminal, and qualify that the maintained Topic schema can represent a bounded living knowledge subject without permitting a generic links-only collection.

## Done Criteria

- The canonical `tiinex.topic.v1` contract accepts maintained, bounded explanatory subjects and rejects an unowned links-only index; no duplicate guide schema or new taxonomy is introduced.
- Getting Started and its relevant Guides explain a complete chat-first journey with host-independent assistant/tooling guidance. Ordinary users are not required to know schema IDs, execute CLI commands, or use one particular extension.
- Qualified schemas and companions remain the authority for artifact details, including user-imported schemas. The manual describes discovery rather than hardcoded types.
- Existing Documentation, Getting Started and Guides ancestry is preserved; integrity checks include the Parent digest cascade and maintain source recoverability from the predecessor carrier.
- Native Start and Getting Started Entry remain portable and do not auto-scaffold or claim authority over unrelated user work.
- Deliver a complete Tiinex Handoff Package V1 with all predecessor Workspaces and tested new Docs bytes; no loose patch carrier.

## Scope

- Owner: Docs for maintained semantics and learning material, with existing Business Documentation And Learning Project as governing Project.
- Human-first, chat-first and target-neutral writing: ChatGPT Web, VS Code/Copilot and future consumers should derive the same qualified content through their own interfaces.
- Prefer qualified existing Core authoring/integrity and Workspace-carrier tooling; avoid alternate formats, new metadata conventions, redundant catalogs or automated project creation.

## Dependencies

- Published, commit-pinned Business Project Parent, as used by the existing Documentation Topic.
- Current Docs Topic schema, Root contract, existing Documentation lineages, and already transported Native Getting Started Entry.

## Interpretation Limits

- A manual correction does not demonstrate that a blind LLM independently discovers Tiinex or that all host integrations are implemented.
- Docs working-tree changes are not claimed to be GitHub-published, accepted, or current in an external repository merely because their integrity checks pass.
