# Docs Major 003 — Anchor And Successor Grounding Evolution

## Objective

Raise cold-start successor grounding from merely operationally recoverable to a level that preserves the current Anchor mental model, process invariants and semantic distinctions without requiring Sigma to reteach lessons already learned through Tooling, process, Role and lineage failures.

## Done Criteria

- Audit current Executive/Operational grounding, Anchor Role context, repository/lineage policy, cold-start grounding mechanics and recent successor-gap material against the current qualified project state.
- Classify each durable lesson at the lowest correct owner: canonical semantics, Anchor Role responsibility, operating process, Tooling enforcement, or transient current-state recovery. Do not collapse all knowledge into one giant grounding document.
- Produce or revise composable Docs grounding material so a fresh Anchor can recover the current mental model without depending on this conversation.
- Explicitly preserve at least these current invariants where they belong: Carrier Major vs artifact filename lineage are distinct; carrier prefix-series progress independently; Major scope does not grow silently; audit before merge; specialist return Workspaces union with current/outbound ancestry rather than wholesale replacement; Business may host reusable Role identity without becoming specialist work owner; Role identity is distinct from session-holder binding; local-first recovery; fail-closed ambiguity; full Sigma test carriers for dependency-sensitive human gates; Playthings presentation is not semantic truth; schema-scalable host authoring should not restate schema semantics; discovered process defects must feed successor improvement rather than remain private Anchor workaround knowledge.
- Review the current Anchor Role and return an exact recommended Role delta that would make the Role describe the actual Anchor responsibility now demonstrated in practice: progression, recovery, lineage audit, ownership routing, human gates, process/tooling evolution, and active reduction of successor knowledge gaps.
- Define a repeatable successor acceptance rubric: cold-start a fresh Anchor, compare its qualified decisions/explanations against current authority, classify delta, improve the correct layer, and repeat until the meaningful gap is negligible.
- Separate stable grounding from fast-moving current status so grounding can evolve without becoming stale merely because one specialist lane finishes.
- Do not convert current implementation observations into canonical semantics without evidence.

## Scope

Docs semantic/grounding artifacts, role/process disposition and successor-test design. Business Anchor Role source is read-only in this Major; return an exact proposed delta for Anchor to apply separately after semantic review.

## Dependencies

- Current Docs Root, lineage policy, repository boundaries and role-authority/grounding artifacts.
- Current Business Anchor Role and latest full recovery as read-only context.
- Current Tooling grounding behavior and recent cold-start evidence as read-only mechanics context.

## Exclusions

- No Core implementation mutation.
- No Business Role mutation under Axiom authority.
- No attempt to encode every current specialist status into canonical semantics.
- No mass rewrite of historical grounding artifacts.

## Acceptance Boundary

The Major is not complete because the prose looks good. It must return a concrete successor-grounding test plan and a bounded set of composable grounding/Role/process changes that can be tested on a genuinely fresh Anchor.
