# Thin-Lineage Anchor Grounding Semantics And Role Review

## Objective

Determine the smallest semantically correct durable model that lets a fresh Anchor recover enough organizational context to orchestrate sparse work without treating Role inventory, package presence, source availability, chat identity or transport filenames as authority.

## Done Criteria

- Review current Role/Party, typed Relation, Handoff Required/Reference Context, Workspace/representation/cache and grounding authority relevant to this problem.
- State whether current semantics already represent an additional relevant participant/capability context beyond Handoff `from`/`to`; if yes, identify the exact owner and binding pattern. If not, state the missing semantic contract precisely without inventing a schema by convenience.
- Distinguish semantic authority from Tooling projection for these source states: complete carried Workspace; bounded/cache material; explicit qualified references/pointers; unavailable authoritative source. Define what may and may not be inferred in each state.
- Classify `grounded-to-act` versus wider orchestration sufficiency. Prefer Role/process/Decision guidance over a new canonical state/schema unless an actual semantic contract requires one.
- Review current Anchor Role continuation and return an exact proposed Business Role delta, if any, covering participant/capability discovery, delegation norm, turn/recovery stewardship and exact-source blockers. Do not mutate Business.
- Preserve the boundary that Anchor may implement when rational/necessary, while normal orchestration should use qualified specialist Roles so Anchor learns actual organizational capability and parallelizes expensive turns.
- Define the blind thin-lineage successor acceptance rubric, including what counts as Sigma correction/reconstruction versus legitimate human gate input.
- Return contradictions to current authority explicitly. Do not encode current chat phrasing as canon merely because it is recent.

## Required Inputs

- Current Docs semantic/grounding source as writable specialist home.
- Current Business Epic, Anchor/Axiom/Loom/Sigma Roles and current grounding/recovery process material as read-only organizational evidence.
- Current Core portable Tooling source as read-only evidence of what mechanics currently project; implementation details do not define semantics.

## Scope

Docs semantic/grounding authority, Role/process disposition and successor acceptance design required by the controlling Business Epic.

## Dependencies

- Current Business Epic and Role artifacts as read-only organizational authority.
- Current Docs Role/Relation/Handoff/Workspace semantics and prior successor-grounding work.
- Current Core portable grounding/package behavior as read-only implementation evidence.
- Parallel Loom return for any implementation findings that reveal a semantic contradiction.

## Exclusions

- No Business source mutation.
- No Core implementation mutation.
- No new schema or relation predicate without demonstrated semantic need and explicit authority.
- No attempt to make every available Role a participant in every session.

## Return Boundary

Return to Anchor with qualified semantic disposition, exact recommended durable Docs/Business deltas, unresolved questions and the smallest Tooling-facing contract Loom can implement without semantic inference.
