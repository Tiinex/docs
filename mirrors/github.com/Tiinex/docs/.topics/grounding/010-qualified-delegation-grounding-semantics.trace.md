# Qualified Delegation Grounding Semantics

## Objective

Define the smallest existing Tiinex semantic/process contract that lets a bounded Anchor convert an explicitly relevant specialist Role/capability into a qualified delegation chain without inventing participation, source authority or transport semantics.

The contract must distinguish: Role capability, current-work relevance, delegation applicability/requiredness, repository-local Task ownership, Handoff transfer authority, return responsibility and later Anchor reconciliation.

## Done Criteria

- State exactly what current-work authority is sufficient to select a delegate/capability for a bounded scope.
- State how Business-root/Epic provenance should connect to a specialist repo-local Task without granting the specialist Business mutation.
- State the minimum semantic chain for Task -> Handoff -> recipient Role -> return/reconciliation.
- Determine whether delegation discipline should be a Process, Role obligation, direct current-work invocation, or composition of existing primitives; add no new schema by convenience.
- Preserve the distinction between “Role is capable/relevant” and “Role is actually delegated/participating.”
- Define fail-closed behavior when delegate, process, source or return authority is missing.
- Return a qualified Axiom-to-Anchor semantic disposition.

## Scope

Docs semantics only. No Core or Business mutation.

## Dependencies

- Business Task: Qualified Delegation Grounding And Transport Discipline;
- accepted blank/minimal Workspace cache grounding disposition;
- accepted process-applicability, holder/source and participant relevance semantics.
