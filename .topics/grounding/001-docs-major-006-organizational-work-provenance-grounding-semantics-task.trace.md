# Docs Major 006 — Organizational Work Provenance Grounding Semantics

## Objective

Classify the repeated `organizational-work-provenance-unresolved` grounding result observed independently by both fresh Anchor probes and define the smallest truthful semantic contract for organizational work provenance without inferring membership or work ownership from Parent, repository, filename, carrier or package placement.

## Done Criteria

- Reproduce the exact informational grounding condition from the accepted fresh-run Evidence and current recovery material.
- Decide whether the grounding slot represents a legitimate missing durable relation/context assertion, an optional context that should remain unresolved, or an over-broad Tooling expectation.
- Reuse existing Tiinex Role/Relation/Party/Project/Workspace semantics when sufficient; do not create a new schema merely to silence a diagnostic.
- Define what, if anything, can truthfully establish that one current work frontier belongs to / is undertaken for the Tiinex organization while preserving repository work ownership, Role identity and semantic Parent independence.
- Identify exact implementation owner split if a correction is warranted: Docs canonical semantics, Business relation/context instance, Core grounding projection, or no change.
- Return one concise Decision/Evidence plus a normal Axiom-to-Anchor Handoff.

## Dependencies

- Standard and perturbed fresh-Anchor Evidence showing the same unresolved organizational-work-provenance slot.
- Current Tiinex organization root and Business Role/Relation semantics.
- Current grounding/context semantics in Docs and Core projection behavior as read-only implementation context.

## Scope

Semantic classification and owner disposition only.

## Exclusions

- No Business instance mutation under Axiom authority.
- No Core implementation mutation.
- No new schema unless existing canonical semantics are proven insufficient.
- No inference of organization membership or work provenance from filesystem/repository/package/Parent adjacency.

## Acceptance Boundary

Success means Anchor knows whether the repeated grounding slot should be resolved, intentionally remain unresolved, or be changed mechanically, and exactly which owner must act next. A green diagnostic is not itself the objective.
