# Educational Root

This topic opens a broader educational line in the `docs` repository.

The purpose of this root is not to decide one output medium too early.

The purpose of this root is to give teaching-oriented material a continuity home
before it narrows into slides, visual explainers, image briefs, or other more
specific branches.

## Current Read

The current need is to keep educational intent broader than any one visual
format.

That means this root should be able to hold or spawn narrower lines such as:

- slide-oriented visual material
- explainer imagery
- prompt or handoff packets for cloud generation
- later educational evidence, critique, or decisions

## Design Direction

For this topic space, current structure should prefer:

- keeping the educational line broad enough to outlive one delivery format
- treating `slides` as one child branch rather than as the whole educational
  surface
- carrying shared educational quality and receiver requirements here before
  narrower branches add their own invariants
- attaching future sibling branches when other educational forms appear
- keeping concrete generation asks in child tasks rather than in the root

## Shared Requirement Hierarchy

This root should carry the broadest educational requirements so narrower
branches do not need to restate them in full.

The current intended hierarchy is:

- level 1: educational continuity and truthfulness across the whole topic space
- level 2: receiver-aware quality expectations that can apply across multiple
  child branches
- level 3: branch invariants that belong inside `slides`, `diagrams`,
  `storyboards`, and other narrower branches
- level 4: audience-specific constraints or mixed-audience constraints inside
  child topics under each branch
- level 5: concrete generation, critique, evidence, or decision tasks inside
  those narrower audience lines

## Shared Educational Requirements

Across this educational topic space, good downstream artifacts should:

- teach or clarify something real rather than only looking polished
- preserve continuity strongly enough that generated outputs can be reviewed,
  criticized, and either rejected or attached back into lineage
- stay truthful about confidence, provenance, and what still needs human review
- remain legible to their intended receivers instead of collapsing into generic
  image-model aesthetics

## Shared Audience Model

Each educational branch should be able to open narrower audience-specific child
topics when one branch needs materially different receiver handling.

The important distinction is not only one audience at a time.

The structure should also support audience combinations when the same artifact
must land for more than one receiver group at once.

Good audience or audience-combination child topics may be needed when:

- terminology density changes between receivers
- visual abstraction level changes between receivers
- review criteria differ between expert, learner, and mixed audiences
- one artifact must teach clearly without flattening expert signal entirely

## Audience Planning Rule

Subtopics such as `slides`, `diagrams`, and `visual-explainers` should tend to
act as invariants for their medium or format.

Audience-specific requirements should usually narrow one level lower than the
branch root so Cloud ChatGPT can first understand the medium invariant and then
apply the receiver-specific constraint set.

## Next Artifacts

- continue a slides-focused child topic from this root
- continue visual-explainer, diagram, storyboard, prompt-pack, and review
  branches when those narrower lines need their own continuity home
- continue audience-specific or mixed-audience child topics under those
  branches when receiver expectations materially change the acceptance bar
- add later educational branches when another medium or teaching format needs
  its own narrower continuity line

## Current Branch Candidates

The current educational root should be broad enough to spawn several narrower
branches without treating any one of them as the whole educational surface.

Current good candidates include:

- `slides`
- `visual-explainers`
- `image-briefs`
- `storyboards`
- `diagrams`
- `prompt-packs`
- `review-and-critique`
- `lesson-sequences`
- `social-cards`
