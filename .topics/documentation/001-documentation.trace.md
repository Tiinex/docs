# Documentation

**New here? Start by talking about what you want to make.** You do not need to know Tiinex terms or run a command to begin a conversation.

Tiinex helps keep useful work understandable over time: what you made, what changed, where information came from, and what someone needs to continue. Your assistant can use qualified Tiinex support where available. You decide what matters to keep.

## Start here

- [Getting Started](getting-started/001-getting-started.trace.md) — a short, chat-first route from an idea to work you can return to.
- [Guides](guides/001-guides.trace.md) — deeper explanations for people who have a specific need, such as coordination, reducing a long history, or handing work over.
- [Schemas](../.schemas/README.md) — authoritative definitions for the kinds of records Tiinex can keep. You do not need to read schemas just to start using Tiinex.

## What this area maintains

This is one ongoing documentation subject, not an exhaustive index of every artifact type. It owns beginner explanations, their discoverability, and the connection between real use and deeper Tiinex guidance. The long-term responsibility belongs to the Documentation And Learning Project in Business.

A guide explains *when and why*. Schemas and companions define *what is valid*. Tooling performs checks and actions. A guide never grants a role, invents a source, or makes a workflow applicable just because it describes one.

## For assistants and other consumers

Meet the user's goal first. If qualified Tiinex material is available, discover current capabilities through the host-supported Tiinex interface, consult relevant current schemas and companions, and choose only the structure that helps. A custom imported schema can be useful even if this documentation never names it. Ask when project ownership or permission is genuinely uncertain.

ChatGPT Web, VS Code/Copilot, viewers, and future consumers may expose the same material in different ways. Keep this documentation as the shared human-readable source; presentation adapters should not maintain parallel normative copies.

## Keeping this documentation useful

Revise examples and explanations when they no longer match a real user's experience. Keep the subject bounded, its parent and provenance truthful, and its history recoverable. Do not turn this area into a links-only folder index or a replacement schema directory.
