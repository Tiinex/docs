# Your First Workspace

Think of a Workspace as the place where a project and its important notes can stay together. Your creative work — a game, a website, a story — is still the main thing. Tiinex helps make it easier to return to it later.

## Start from the chat

Tell the assistant what you want to do. If you already have a Tiinex package, attach it and ask the assistant to continue from its supplied starting point. You should not have to inspect hidden files or run a terminal command yourself.

If you have only an empty folder, ask your assistant how to prepare it for Tiinex. A supported extension or local integration may offer an Initialize Workspace action; in a host without that ability, the assistant should explain what preparation is needed rather than claiming the folder was initialized. A Workspace can be local without Git.

Once prepared, the assistant can orient the qualified package or Workspace, check what it contains, and help with your goal. An empty Workspace is not a mistake and does not need invented tasks, identities, or roles.

## When does work belong here?

Being attached or open does not automatically make every new idea part of this Workspace. When it matters, the assistant can ask: *“Should I keep this with your current project so we can continue later?”* Decide this before silently mixing separate projects or making changes across repositories.

## If your project grows

Work can live across more than one Workspace. Each should retain responsibility for its own material, with qualified links between related work where appropriate. See [Organizations and multi-Workspace work](../guides/001-2-organizations-and-multi-workspace-work.trace.md).

A Workspace package is not permission to publish, modify remote code, or assign anyone a responsibility. It is a source to understand and, where authorized and supported, continue from.
