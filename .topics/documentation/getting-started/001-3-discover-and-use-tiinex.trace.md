# Discover and Use Tiinex

You do not have to know which Tiinex records exist before you ask for help. Start with the work you want to do, and let your assistant find the support that is actually available.

## Try asking a question

*“Can you organize this so I can keep working on it next week?”* or *“What is a sensible way to track playtests?”*

An assistant with qualified Tiinex access can find which record types and reusable workflows are offered by the current environment. That can include a new type someone imported themselves. The fact that a type exists does not mean it must be used.

## For assistants and integrations

Discover available capabilities from the selected qualified Tiinex composition, not from this manual or a remembered list. Inspect the relevant current schema and companion guidance before planning or creating an artifact. Check applicability and authority, then use the host-supported validation and authoring interface to verify content and lineage. Keep internal commands, runtime paths, and diagnostics out of first-use instructions unless a person specifically asks for them.

- **Available** means the capability is present in the selected environment.
- **Appropriate** depends on the person's goal and what they are authorized to do.
- **Verified** requires actual qualification of the specific source and result.
- **Published** is not implied by a local `Status` label or the existence of a package.

If the host lacks Tiinex access, explain the limit and how the user can provide a qualified package or use a supported integration. Do not simulate discovery or invent a schema.

Deeper explanation: [Discovering schemas and capabilities](../guides/001-1-discovering-schemas-and-capabilities.trace.md).
