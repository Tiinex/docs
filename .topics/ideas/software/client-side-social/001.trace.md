# Client-Side Social

This topic narrows the software branch into a specific product direction: a
social client that treats lineage, local control, and exportability as product
invariants rather than hidden implementation details.

## Current Read

The attached artifact suggests a clear product claim:

social media should behave more like an open protocol plus portable user-owned
context than a cloud-hosted identity prison.

The important idea is not only "another social app".

The important idea is letting users choose or connect lineage spaces, publish
from local state, sync optionally, and export anytime.

## Artifact Grounding Read

The current attached artifact especially suggests these product signals:

- client-side first storage and operation
- user choice of lineage or context home
- local-first persistence with later optional sync
- portable export rather than captive platform dependence
- readable and machine-usable continuity
- open-form, protocol-like interaction rather than centralized account lock-in

## Design Direction

This line should continue as a product topic, not yet as a protocol spec or one
UI mock only.

Good continuation should usually prefer:

- keeping user-owned continuity as the top invariant
- separating publishing, synchronization, lineage selection, and export into
  explicit product surfaces
- delaying network/protocol and cryptographic decisions to later children
- preserving space for both personal and team-oriented use cases

## Good Child Candidates

- `lineage-selection-and-homes`
- `publish-and-sync-model`
- `portable-export-and-backup`
- `local-first-social-ux`
- `protocol-and-interoperability`

## Next Artifacts

- attach public-surface or implementation grounding later when this line needs
  stronger software proof
