# Recoverable Context Apps

This topic narrows the software branch into a family of practical apps that use
lineage as the working substrate rather than as hidden metadata.

## Current Read

The attached artifacts suggest a coherent software family with one shared idea:

context should stay recoverable as work moves between people, decisions,
meetings, evidence, and public proof surfaces.

The family read is not just "more apps".

The family read is software that makes continuity operational for everyday work.

## Artifact Grounding Read

The current attached artifacts point especially toward these app concepts:

- a decision builder that turns reasoning into traceable decisions
- a meeting capture console that preserves actionable meeting context
- a trace explorer that reads the chain instead of just the summary
- a handoff pad that passes work with context intact
- a root cause finder that follows the graph backward
- a public provenance viewer for shareable, read-only proof surfaces

## Design Direction

This line should continue as a product-family topic above narrower apps.

Good continuation should usually prefer:

- keeping the shared continuity model here
- opening app-specific children only when the workflow materially diverges
- preserving receiver clarity for each app concept
- delaying architecture and packaging choices until later children

## Shared Product Invariants

Across this family, strong downstream app ideas should usually preserve:

- readable continuity for humans
- machine-usable structure for automation and retrieval
- explicit parent, origin, evidence, and handoff surfaces where relevant
- recoverability when one app is not the only reader of the data
- export and portability rather than lock-in to one runtime

## Good Child Candidates

- `decision-builder`
- `meeting-capture-console`
- `trace-explorer`
- `handoff-pad`
- `root-cause-finder`
- `public-provenance-viewer`

  technical grounding or UI proof
