# Trace Explorer

This topic narrows the recoverable-context app family into a specific reader:
an app for exploring the trace chain as a navigable graph instead of as a pile
of markdown files or one condensed answer.

## Current Read

The strongest product value here is interpretability.

Users should be able to inspect:

- what this artifact is
- what parent it continues
- what origin grounded it
- what evidence, decision, feedback, or reduction relations surround it
- what is missing, unresolved, or only partially reconstructed

## Design Direction

Good continuation in this line should usually prefer:

- graph legibility over flashy visualization
- reader trust over automated overinterpretation
- explicit distinction between parent and origin
- clear support for partial or broken lineage instead of pretending the graph is
  always complete

## Likely Receiver Humans

Strong downstream artifacts here should usually stay useful for:

- operators tracing work backward
- reviewers checking provenance
- investigators reconstructing failure or drift
- teams onboarding into an existing lineage without prior chat context

## Good Child Candidates

- graph navigation and filtering
- missing-link and broken-lineage handling
- evidence and decision overlays
- reconstructed summary versus raw trace views
- openable source and export flows

## Next Artifacts

- continue narrower children when one reader workflow becomes clear enough to
  deserve focused design work
- attach runtime or provenance-side grounding later when this line needs stronger
  implementation evidence
