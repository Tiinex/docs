# Hardware Ideas Branch

This branch holds ideas where the downstream continuation should remain aware of
physical components, real-world constraints, fabrication, deployment, or
device-level ownership.

## Current Read

The current need is not to enumerate hardware products immediately.

The current need is to preserve a continuity lane where later LLM expansion can
stay grounded in:

- physical constraints
- prototyping cost
- deployment environment
- maintenance burden
- receiver-specific build realities

## Design Direction

For this branch, continuation should usually prefer:

- ideas that stay honest about physical implementation constraints
- separating concept exploration from premature engineering detail
- preserving the difference between hardware concept, proof path, and eventual
  productization
- opening narrower children only when a concrete device, environment, or use
  context becomes clear

## Good Child Shapes

Likely useful child shapes include:

- sensors and measurement
- industrial or field deployment
- embedded workflow support
- home or consumer devices
- maintenance and observability around physical systems

## Next Artifacts

- continue narrower hardware lines only when one concrete use context becomes
  clear enough for serious follow-up
- attach software, evidence, or workflow companions later when a child needs a
  mixed hardware-software continuation path
