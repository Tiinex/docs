# Ideas Root

This topic opens a broad continuity home for ideas that are expected to be
expanded later by other language models together with human review.

The purpose is not to prove every idea now.

The purpose is to create enough lineage and routing clarity that later work can
continue coherently instead of restarting from a blank sheet.

## Current Read

The current directory structure already carries an important decision:

- idea expansion should follow receiver-relevant branches
- the branch shape should help later humans know which ideas belong to their
  lane
- the first generation of traces should stay broad enough to allow many child
  ideas later
- the traces should preserve coherence and handoff quality rather than trying
  to finish every domain in one pass

## Design Direction

For this topic space, current structure should prefer:

- using folder boundaries as continuation boundaries
- treating each branch as a human-routing lane rather than only a taxonomy
- writing branch roots that are strong enough for another LLM to continue with
  minimal reinterpretation
- keeping concrete productization, implementation proof, and evidence gathering
  in later children rather than in this root
- attaching repo-specific grounding later when a narrower branch actually needs
  it

## Continuation Rules

Good child topics under this root should usually preserve at least these
signals:

- who the likely human-in-the-loop receivers are
- what kind of problem or opportunity the branch is expected to hold
- what kinds of narrower ideas should become children instead of being merged
  back into the branch root
- what future evidence, task, or decision artifacts might be needed before an
  idea can be treated as implementation-ready

## Current Branch Candidates

The current folder structure suggests these first continuation lanes:

- `business`
- `diy`
- `hardware`
- `software`
- `de-centralized-internet`

The `business` lane already narrows further into:

- `it`
- `sales`

## Multi-Root Use

This topic root should remain a continuity and routing surface inside `docs`.

Later children may still ground themselves with support from other repositories
in the workspace when a narrower idea needs provenance, runtime examples,
feedback evidence, public-surface framing, or implementation context.

## Next Artifacts

- open branch roots for `business`, `diy`, `hardware`, and `software`
- open the cross-cutting branch root for `de-centralized-internet`
- open child roots for `business/it` and `business/sales`
- continue narrower idea lines only after the branch roots clarify receiver,
  scope, and expected follow-on artifacts
