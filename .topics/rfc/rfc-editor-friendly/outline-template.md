# RFC Outline Template

Use this as a drafting scaffold, not as a forced serialization.

Title: <working title>

## Abstract

State what the document defines in a few sentences.

## Problem Statement

Explain the concrete continuity or recovery problem.

## Design Goals

List the goals the model is optimizing for.

## Local Constraints Or Policy

Optional.

Use only when the topic needs explicit local steering that is not
already clear from lineage or the surrounding environment.

## Model

Describe the minimum model.

For example:

- primary parent relation
- optional origin relation
- type and schema identification
- integrity footer model

## Required Elements

State what an implementation or artifact must carry.

## Optional Elements

State what remains conditional or context-dependent.

For example:

- optional local policy layer
- optional rules or constraints layer
- optional origin relation
- optional reference set

## Examples

Keep examples short.

Use only the examples that actually sharpen the model.

## Operational Guidance

Describe the preferred workflow for producing and maintaining the
artifacts.

## Security Or Integrity Considerations

Explain what the integrity model does and does not protect.

## Open Questions

List unresolved issues explicitly.

## References

Prefer a consistent citation style throughout the document.
