# Docs RFC Continuation (Draft)

This artifact starts the first repository-local RFC continuation inside
`docs`.

The parent is intentionally the local cross-origin root rather than the
upstream `.github` leaf. That keeps the continuity model simple:

- `.github` remains the published origin that seeded this topic space
- `docs` now carries its own local lineage forward
- later `docs` children should continue from `docs` parents first

---

## Current Reading

The present RFC family has already established a lightweight envelope
pattern around human-readable bodies:

1. `Parent Trace` provides the primary lineage edge
2. `Origin` is optional and only needed when inherited recovery is not
   safely local
3. `Type` and `Schema` distinguish artifact shape without forcing one
   universal body format
4. integrity belongs in a footer so the main body can remain readable

That model is strong enough to keep using in `docs` without importing
the entire `.github` drafting cadence.

---

## Naming Alignment

The next naming step should preserve structural alignment across repos
without collapsing topic artifacts into provenance exports.

Current grounded read:

- `ai-provenance` uses numeric lineage first, then an optional slug
- topic-oriented artifacts benefit from process-oriented slugs because
  they make transitions legible to humans
- those two ideas are compatible rather than opposed

Practical consequence for `docs` topic-facing traces:

- prefer lineage-first names such as `001-1-grounding.trace.md`
- avoid type-first names such as `.topic.trace.md`
- let the slug describe the transition or working state, not the whole
  ontology of the file

This keeps the naming legible to people while staying structurally close
to the existing provenance lineage model.

---

## Local Continuation Rule

From this point, the conservative continuation rule in `docs` should be:

1. continue the local `docs` parent chain first
2. treat upstream `.github` artifacts as origin or reference material,
   not as the direct parent once the local root exists
3. only introduce `Origin` again when a future child depends on an
   external recovery anchor that is not already inherited through the
   local parent chain

This keeps one primary home for the local continuation signal.
